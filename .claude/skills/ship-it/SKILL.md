# Ship It (CSC12004 HomeStay Dorm)

> Generated by `specialize-skill` from the general `ship-it` skill for
> `dinhdaivu/CSC12004_Information-Systems-Analysis-and-Design`. Concrete to THIS
> repo. Re-run `specialize-skill ship-it` after the general skill changes.

Gated pipeline from "code written" to "PR open and green". **Orchestrator only** —
it composes other skills + the project's npm scripts.

**Local gates mirror GitHub Actions** (`.github/workflows/backend-ci.yml`,
`frontend-ci.yml`) so passing locally predicts a green PR. CI runs on
`pull_request` to `main`/`develop`, triggered by `backend/**` / `frontend/**`
path changes — match that in Step 0.

## Rules of engagement

- Sequential & gated: **stop at the first failed gate**, show real output, let the
  user fix/override/abort. Never continue past a red gate silently.
- Commit and PR need explicit confirmation. Read-only gates run freely; results gate.
- Flags via `$ARGUMENTS`: `--skip-tests`, `--skip-security`, `--draft`, `--no-pr`,
  `--no-watch`. Report any skip — never silently.
- End with a per-stage status table (✅ / ❌ / ⏭️).

## Step 0 — Preflight

- `git rev-parse --abbrev-ref HEAD` — must not be `main`. Else stop.
- Changed areas from `git diff main...HEAD --stat` + `git status`:
  - `backend/**` → **backend** (CI: backend-ci.yml will run)
  - `frontend/**` → **frontend** (CI: frontend-ci.yml will run)
  - `supabase/migrations/` → **db** (no CI lint/test; note migration must be applied)
  - `docs/` only → **docs** (no CI; skip build/test, go to reviews)
- No changes vs `main` → stop.

## Step 1 — Lint (gate)  — mirrors CI "Run linter"

```bash
cd backend  && npm run lint     # autofix: npm run lint:fix
cd frontend && npm run lint     # autofix: npm run lint:fix
```
On failure: show errors, offer `lint:fix`, stop until clean.

## Step 2 — Build (gate)  — mirrors CI "Build" (do NOT skip; TS strict)

```bash
cd backend  && npm run build
cd frontend && npm run build
```
This catches TypeScript-strict errors that lint+test miss. On failure: stop.

## Step 3 — Test (gate)  — mirrors CI "Run tests"  (skippable: `--skip-tests`)

```bash
cd backend  && NODE_ENV=test npm test -- --coverage   # CI uses a postgres:15 service
cd frontend && npm run test:ci                         # NOT `npm test`
```
Coverage target >70%. On failure: surface output and stop. Note: backend tests
that need Postgres may behave differently locally than in CI's service container —
call that out rather than masking a failure.

## Step 4 — Code review (gate)

Invoke the **`code-review`** skill on the current diff. Summarize findings; if it
finds high-confidence bugs, ask whether to fix before continuing.

## Step 5 — Security review (gate)  (skippable: `--skip-security`)

Invoke the **`security-review`** skill. Treat high-severity findings as blocking
unless overridden (JWT/auth, RLS, payments, Cloudinary uploads, OpenAI chatbot).
Complements the repo's `codeql.yml` scan — it does not replace it.

## Step 6 — Commit (confirm)

- Stage intentionally (`git add <paths>`); ask before `add -A` if unrelated files
  are dirty.
- Message convention: **`type(scope): subject`** (type ∈
  feat/fix/docs/style/refactor/perf/test/chore; scope ∈ backend/frontend/docs/db).
- Show message + staged files, get a go-ahead, then commit on the feature branch.

## Step 7 — Open PR (confirm)  (skip with `--no-pr`)

Invoke the **`open-pr`** skill — fills `.github/pull_request_template.md` from the
diff, links the issue (`Closes #n`), carries labels, **adds no reviewers**.

## Step 8 — Watch CI  (skip with `--no-watch`)

After the PR is created, watch the real CI checks and report pass/fail:
```bash
gh pr checks --watch        # on the PR's branch; or: gh pr checks <n> --watch
```
If a check goes red, surface it (`gh run view <run-id> --log-failed`) and offer to
fix — the local gates should have caught it, so a red CI here means a gap to learn from.

## Step 9 — Report

Per-stage status table, commit hash, PR URL, and final CI status. Note skipped
stages and manual follow-ups (add reviewers; if `supabase/migrations/` changed,
apply per `.agent/workflows/db-migrations.md`).
