# Open PR (CSC12004 HomeStay Dorm)

> Generated by `specialize-skill` from the general `open-pr` skill for
> `dinhdaivu/CSC12004_Information-Systems-Analysis-and-Design`. Concrete to THIS
> repo. Re-run `specialize-skill open-pr` after the general skill changes.

Turn the current branch's work into a GitHub PR. Outward-facing — **confirm
before creating.**

> **Reviewers:** never add reviewers automatically — the user adds them. Do not
> pass `--reviewer` unless explicitly asked in the conversation.

Fixed facts: GitHub (`gh`), repo `dinhdaivu/CSC12004_Information-Systems-Analysis-and-Design`,
base branch `main`, PR template `.github/pull_request_template.md`.

## Step 1 — Resolve context

```bash
BRANCH=$(git rev-parse --abbrev-ref HEAD)   # must not be main
```
- Linked issue: parse `#<n>` from the branch (e.g. `chore/#72-...` → 72); else ask.
- Push if needed: `git push -u origin "$BRANCH"`.
- Verify auth: `gh auth status` (stop with `gh auth login` if not authed).

## Step 2 — Build the PR body (grounded in the diff)

- `git diff main...HEAD --stat` + content for the touched areas.
- Fill `.github/pull_request_template.md` with real content (no `<!-- -->` left):
  - **Summary** — what changed and why.
  - **Related References** — `Issue: #<n>`; cite existing `docs/tasks/...`, `docs/UC/...`.
  - **What Changed** — tick Frontend/Backend/Database/CI/Docs/Tests per the diff.
  - **Source Of Truth Check** — tick `docs/architecture/api-endpoints.md`,
    `database.md`, relevant `docs/tasks/` / `docs/SUC/` if the change affects them.
  - **Verification** — the exact commands (`cd backend && npm test`, `npm run lint`,
    `cd frontend && npm test`, etc.).
  - **Checklist / Breaking Changes / Follow-Up** — fill honestly.
- Add **`Closes #<n>`** so merge closes the issue.
- Write the body to `.claude/drafts/draft-pr.md` (frontmatter: `title`, `base`,
  `head`, `issue`, `labels`, `draft`) for review/reuse.

## Step 3 — Title & labels

- **Title** — conventional-commit style matching this repo's commits:
  `type(scope): subject` where type ∈ feat/fix/docs/style/refactor/perf/test/chore
  and scope ∈ backend/frontend/docs/db. Append ` (#<n>)`. Fall back to the issue's
  `[Tag] ...` title if clearer. Example: `chore(backend): migrate to Spring Boot 4.0.6 (#72)`.
- **Labels** — carry over the issue's labels that exist (`task`, `enhancement`,
  `bug`, `documentation`, ...). Skip missing ones; never auto-create without asking.
- **Draft** — ready by default; `--draft` only if the user asks.

## Step 4 — Confirm, then create (no reviewers)

Show title, `main ← <branch>`, linked issue, labels, draft/ready, body preview.
Get a go-ahead. Then:

> ⚠️ **Always strip YAML frontmatter before `--body-file`** — passing the raw
> `draft-pr.md` puts the `---…---` block at the top of the GitHub PR description
> as raw text. The `awk` below strips it.

```bash
REPO="dinhdaivu/CSC12004_Information-Systems-Analysis-and-Design"
tmp=$(mktemp)
awk 'BEGIN{fm=0} /^---[[:space:]]*$/{fm++; next} fm>=2{print}' \
  .claude/drafts/draft-pr.md > "$tmp"
gh pr create --repo "$REPO" --base main --head "$BRANCH" \
  --title "<title>" --body-file "$tmp" --label "<label>"
rm -f "$tmp"
```
No `--reviewer` / `--assignee` unless the user explicitly asked.

## Step 5 — Report back

- Print the PR **URL**.
- Remind the user to **add reviewers themselves** (and assignees/milestone if wanted).
- Offer follow-ups (don't run without asking): `gh pr ready` (if draft),
  `gh pr view --web`, or remove `.claude/drafts/draft-pr.md`.

## Quality bar

- Never create a PR without explicit confirmation.
- Body grounded in the real diff; no template placeholders left; `Closes #<n>` present.
- No reviewers added (hard rule).
- Surface real CLI output (URL/errors); never claim success you didn't see.
